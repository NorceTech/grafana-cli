# src/commands/

## OVERVIEW

One module per command family; each owns its clap types and turns Grafana datasource-proxy JSON into a `CommandOutput`. Own file because it is a distinct domain: per-datasource wire formats and the stable JSON output contracts. Families are subdirectories (`logs/`, `metrics/`, `traces/`); `prom.rs` holds the wire-format code they share.

## CONTRACT

- Query command: `pub async fn name(client: &GrafanaClient, profile: &str, mode: OutputMode, args: &NameArgs) -> crate::Result<CommandOutput>`, where `NameArgs` is the command's `#[derive(clap::Args)]` struct; a windowed command takes `Windowed<'_, NameArgs>` (the args plus the resolved `Bounds`) instead of `&NameArgs` (`logs::labels` / `logs::label_values` take `Windowed<'_, QueryWindow>` plus the label and optional `--match` selector). `profile` is only used to tag `LogRecord`s.
- Dispatch: `app::dispatch` calls `Query::resolve` once, before fanout, then `Resolved::run` once per profile through `fanout::run`; `Resolved::run` in `mod.rs` delegates to each family's `#[derive(clap::Subcommand)]` enum (`LogsCmd`, `MetricsCmd`, `TracesCmd`), whose `run(&self, client, profile, mode, bounds)` matches its variants. The bin flattens `Query` into its `Commands`.
- Pipeline: `client.datasources()` -> `datasource::resolve(&all, Kind::Loki | Kind::Prometheus | Kind::Tempo, flag)` -> `client.proxy_request(&ds.uid, "<api path>", &pairs)`, a `Reply` (JSON `body` plus the path, status and content type in `meta`) -> reshape `reply.body`.
- Proxy paths (relative, no leading slash): Loki `loki/api/v1/query_range`, `loki/api/v1/query` (`instant`), `loki/api/v1/labels`, `loki/api/v1/label/{label}/values`; Prometheus `api/v1/query`, `api/v1/query_range`, `api/v1/labels`, `api/v1/label/{label}/values`, `api/v1/series`, `api/v1/query_exemplars`; Tempo `api/traces/{id}`, `api/search`, `api/v2/search/tags`, `api/v2/search/tag/{tag}/values`. `proxy_request` is GET-only with query pairs. `{label}`, `{id}` and `{tag}` come from the command line and reqwest resolves `..` in a path, so `Query::validate_path_args` checks them before fanout (`logs::validate_label_name`: `[A-Za-z_][A-Za-z0-9_]*`; `traces::validate_trace_id`: 1 to 32 hex digits; `traces::validate_tag`: `[A-Za-z0-9_.:-]` but not `.` or `..`); anything else is `Error::Config` (exit 2) and nothing is requested.
- Wire time units: Loki takes ns strings (`to_ns_string`), Prometheus fractional epoch seconds (`to_epoch_secs`), Tempo search whole epoch seconds (start floored, end ceiled; Tempo answers a fraction with 400). Windows are resolved once per invocation: `Query::resolve` feeds the variant's `QueryWindow` (found by the exhaustive `Query::window` match) to `timeutil::resolve_window`, so a bad window is one config error before fanout and every profile queries the same `Bounds`. Commands never read `--since` / `--from` / `--to` themselves. `resolve_window` also rejects bounds outside the i64 nanosecond range (1677-09-21 to 2262-04-11) with a config error naming the flag.
- The command shapes tables itself: return `CommandOutput::Table { headers, rows }` when `mode == OutputMode::Table`, else `Json` / `Logs`. Table rows are built only in table mode; JSON mode never allocates them.
- Variants: `Logs` = `LogRecord`s rendered as JSONL; `Json` = reshaped value with stable field names (a lossless upstream passthrough is `Json` too, like `traces get`).
- Always a JSON array, `--output table` ignored: `logs labels`/`label-values`, `metrics labels`/`label-values`, `traces tags` (discovery names are query-building input, not rows).

## CONVENTIONS

- Deterministic output: logs sort by (ns timestamp, line), never by the ms-truncated `ts` string (`logs/search.rs`); range and matrix series sort by `label_string` (sorted keys), samples by ts; discovery series by label string; exemplars by (series label string, ts); tag names sorted and de-duplicated; tag values by (type, value).
- Field names are README contracts: instant/range/loki-metric `{metric, value, ts}` with values kept as upstream strings; exemplars `{metric, labels, value, ts}`; traces search `{traceID, rootServiceName, rootTraceName, durationMs, start}`; tag values `{type, value}`; datasources `{name, type, uid, url, isDefault}` plus `health`/`healthMessage` under `--check`.
- Errors: a 2xx reply of the wrong shape (no `data`, wrong `resultType`, a malformed stream or entry) is `reply.malformed(what)`, an `Error::Response` carrying the reply's status and naming its path, content type and first 200 chars. Prometheus and Loki replies pass `success_data` (`mod.rs`) first: `"status": "error"` is `Error::Http` with the upstream `error`, any other status is malformed. Bad `--at`/`--step`/`--interval` input is `Error::Config` (exit 2).
- Typed until the wire: datasource types are `datasource::Kind`, Loki's direction is `logs::Direction`, Tempo's tag scope is `traces::TagScope`; each becomes a string only via its `as_str()` where the request or the type filter is built.
- Recoverable data oddities (non-numeric sample ts, unknown trace shape) are skipped with `eprintln!("note: ...")`.
- Profile commands return JSON action objects (`{"action": "add", "profile", "auth"}`) and call `config.save()` themselves; only `list` honours `--output table`.

## ADDING A COMMAND

1. `#[derive(clap::Args)]` struct and function in the family module per the contract; `#[command(flatten)]` a `QueryWindow` for time-windowed queries, whose function takes `Windowed<'_, NameArgs>`. `//` comments only on clap-derived items: `///` becomes help text.
2. Variant in the family's `*Cmd` enum plus its arm in that enum's `run`, plus arms in `Query::window` and `Query::validate_path_args` (`mod.rs`; the compiler flags a missing arm); an argument that becomes a proxy path segment gets a validator there. A new family also needs `pub mod`, a `Query` variant and a `Resolved::run` arm in `mod.rs`.
3. No bin change: `Commands` flattens `Query`. Only commands that must not fan out (like `profile`, `completions`) get a variant in `src/cli.rs` and an arm in `src/app.rs::run`.
4. Unit tests for pure reshaping in the module; a wiremock scenario in `tests/`.

## ANTI-PATTERNS

- Never query an explicit `--datasource` of another core type, and never reject one of a plugin type. `datasource::resolve` matches uid or name, then `check_type` (`src/datasource.rs:38`) sorts the match by type. The command's own type is used silently. Another core type (`loki`, `prometheus`, `tempo`; a Loki datasource for `metrics range`, say) is `Error::Config` (exit 2) naming both types, raised before anything is proxied. Any other type is a plugin, queried anyway with one `note: datasource '<name>' is type <type>, expected <wanted>; querying it anyway` stderr line, because Prometheus-compatible plugins (VictoriaMetrics, Amazon Managed Prometheus) have their own type.
- No per-command HTTP or auth handling: `GrafanaClient::get_json` owns bearer/basic/OAuth headers, the single OAuth 401 retry and, through `Error::http`, the non-2xx error message (JSON `message`, else JSON `error`, else the plain-text body).
